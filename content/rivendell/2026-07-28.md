==TODO==: Figuring out web-components, hypermedia first frameworks and history of hypermedia

The problem with the modern web framework is that they are bloated as fuck. They come up with components which is essentially a primitive that wraps html, css and js all in one file. These components can be composed together to describe the UI and make it interactive. 
Almost all of them have a reactive data model which makes the UI reactively change as the data changes. These frameworks also support something called SPA which uses a single web page for the whole app.
The obvious problems with these are those of SEO and huge initial payload sizes. These are handled by variety of techniques like SSR, SSG. Now modern react allows for react server components and Suspense which allows for streaming SSR powered by its interruptible rendering architecture based upon its "reconciler" rendering engine.
This might be super useful for developing extensive "manipulation software" or large scale "communication software" like X, Bluesky etc. Even for heavy information software, requiring a lot of complicated context specific graphics and data loading like huge dashboards, might these frameworks serve as useful candidates. But for small scale blogs, websites, apps that might require minimal interaction there is new paradigm of html first frameworks that aim at cutting this bloat. See: [[Information Design by Bret Victor]]. and [AHA Stack](https://flaviocopes.com/the-aha-stack/) by Flavio Copes.

They are hypermedia first frameworks.
Frameworks like [Daisy UI](https://daisyui.com/) also help you to easily style these html elements. However I still feel the current span of html elements aren't enough for developing digital garden. We can use web components to extend the basis set of these html elements! This is what I want to do with [[mycelium - wood wide web]]. Can we do something to have better support for Obsidian too?
